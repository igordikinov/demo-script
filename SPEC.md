## 3. Модель данных

### 3.1 Сценарий (`src/model/schema.ts`)

```ts
export const StepSchema = z.object({
  id: z.string().min(1),            // «1.10» — всегда строка
  title: z.string().min(1),
  action: z.string(),               // пустая строка = не заполнено
  screen: z.string(),               // название экрана
  url: z.string(),                  // абсолютный http(s)-URL или ''
  value: z.string(),                // бизнес-ценность, посыл клиенту
  result: z.string(),
  comment: z.string(),
  node: z.string(),                 // id узла карты процесса или ''
});
export const BlockSchema = z.object({
  n: z.number().int().positive(),   // порядковый номер листа среди листов-блоков, с 1
  title: z.string().min(1),
  sheet: z.string(),                // имя листа — для отчёта
  steps: z.array(StepSchema).min(1),
});
export const ScenarioSchema = z.object({
  schema: z.literal(1),
  id: z.string().regex(/^(my-)?[a-z0-9-]+$/), // общий: имя файла; мой: my-… (§3.6)
  source: z.enum(['repo', 'local']),
  title: z.string().min(1),
  module: z.string(),               // «SNP», «MRP» или ''
  map: z.enum(['snp', 'mrp']),      // какая карта процесса
  fileName: z.string(),
  loadedAt: z.string(),             // ISO; общий — дата последнего коммита файла, мой — время загрузки
  blocks: z.array(BlockSchema).min(1),
});
```

`readWorkbook` (§3.3) отдаёт сценарий без `id`, `source` и `loadedAt` — их проставляет тот, кто сохраняет: библиотека (§3.6) или сборка общих (§3.7).

Все типы — `z.infer`. Поля шага, которых нет в файле, — пустые строки, не `undefined`: карточка различает только «заполнено / нет».

### 3.2 Контракт Excel (`src/excel/columns.ts`)

**Листы.**

- Лист, имя которого начинается с `_`, — служебный и в блоки не попадает.
- `_Сценарий` (необязательный): колонка A — ключ, B — значение. Ключи: `Название`, `Модуль`, `Карта` (`snp` | `mrp`, по умолчанию `snp`). Без листа название сценария = имя файла без расширения, модуль пустой.
- Каждый прочий лист — **блок**, в порядке листов в книге. Номер блока `n` — позиция среди листов-блоков.

**Строка заголовков** ищется в строках 1–3 листа: первая строка, где найдены обе обязательные колонки. Если над ней есть строка с непустой ячейкой A — это **название блока**. Иначе название блока = имя листа.

> Отступление от задания для Claude Design: там строка 1 названа «заголовком сценария». Имя листа Excel ограничено 31 символом, а названия блоков длиннее («Мониторинг, сценарии, интеграция» — 32 символа, с префиксом «Блок 3 · » — 41), поэтому строка 1 несёт название **блока**, а название сценария живёт в `_Сценарий`.

**Колонки.** Порядок любой. Заголовок сравнивается после нормализации: нижний регистр, `ё→е`, пробелы схлопнуты, по краям обрезаны знаки `.:*`.

| Поле | Заголовок в шаблоне | Принимаемые алиасы | Обязательна |
|---|---|---|---|
| `id` | `№ шага` | `№`, `номер шага` | да |
| `title` | `Шаг` | `название шага` | да |
| `action` | `Действие` | `действие (что показывает презентер)` | нет |
| `screen` | `Экран` | `экран / раздел системы` | нет |
| `url` | `Ссылка` | `url`, `ссылка на экран` | нет |
| `value` | `Бизнес-ценность` | `бизнес ценность`, `посыл клиенту` | нет |
| `result` | `Ожидаемый результат` | — | нет |
| `comment` | `Комментарий` | `комментарий / подсказка` | нет |
| `node` | `Узел карты` | `узел процесса`, `узел` | нет |

Колонка с нераспознанным заголовком пропускается (I01). Колонка `Узел карты` в задании для Claude Design не описана — её добавил прототип v2 (секция «Карта процесса»); сопоставление шага узлу должно откуда-то браться, и источник правды — тот же файл.

### 3.3 Разбор (`src/excel/read.ts`)

`readWorkbook(buf: ArrayBuffer, fileName: string, snapshots): { scenario?: Scenario; report: ReportRow[]; summary: Summary }` — чистая функция без DOM, работает в Vitest.

1. `XLSX.read(buf, { type: 'array', cellDates: false })`. Исключение → E01, остальное не выполняется.
2. Текст ячейки: `cell.w` (отображаемый текст), если есть, иначе `String(cell.v)`; `trim()`. Для `id` это принципиально: `1.10` в текстовой ячейке остаётся `1.10`. Если ячейка `id` числовая (`cell.t === 'n'`) — берётся `cell.w` и выдаётся W03.
3. `url`: если у ячейки есть гиперссылка (`cell.l.Target`), берётся цель ссылки, а не текст («Открыть» → URL).
4. Строки ниже заголовка, у которых пусты **все** распознанные колонки, пропускаются молча. Остальные — шаги в порядке строк.
5. Номер строки в отчёте — номер строки Excel (с 1), как видит автор.
6. Проверки §3.5 выполняются по ходу; сценарий возвращается, только если нет ни одной `danger`.

`Summary`: `{ sheets: число листов-блоков, blocks, steps, withLink, withNode }`. Текст сводки: `«{sheets} {листа} → {blocks} {блока} · {steps} {шагов} · {withLink} со ссылкой»` с плюрализацией (`src/i18n/plural.ts`, ТК 23).

### 3.4 Снимок карты процесса (`src/data/pm/<map>.json`)

Навигатор не ходит в сеть за картой. Узлы берутся из снимка, собранного из репозитория `process-map`:

```bash
npm run pm:snapshot -- --from ../process-map          # локальный клон
npm run pm:snapshot -- --from https://raw.githubusercontent.com/igordikinov/process-map/main
```

Скрипт читает `src/data/snp/process.json` и `src/data/mrp/process.json`, пишет:

```json
{
  "map": "snp",
  "title": "…",
  "sourceUpdatedAt": "…",     // updatedAt карты
  "snapshotAt": "2026-09-16",
  "stages": [{ "number": 1, "title": "Обогащение прогноза заказами" }],
  "nodes": { "urovni-sz": 4 }  // id узла → номер этапа
}
```

Вывод детерминирован (ключи отсортированы, отступ 2, LF). Файлы коммитятся. Дата снимка выводится в отчёте проверки (I03), чтобы автор понимал, против какой версии карты проверены узлы.

Факт на 16.09.2026: в прототипе v2 из 27 сопоставлений 4 указывают на узлы, которых на карте SNP нет: `raschet-plana-popolneniya-raspredeleniya` (2.5), `vnesenie-ruchnyh-korrektirovok` (2.10), `rabota-s-monitorom-preduprezhdeniy` (2.11), `tlb` (3.7). В фикстуре они заменены (§11, вопрос 1), 3.7 оставлен без узла.

### 3.5 Проверки (`src/excel/validate.ts`)

Уровни: `danger` блокирует загрузку, `warning` и `info` — нет.

| Код | Уровень | Условие | Сообщение (`ru.ts`) |
|---|---|---|---|
| E01 | danger | файл не читается как книга Excel | «Файл не читается как книга Excel (.xlsx)» |
| E02 | danger | нет ни одного листа-блока с шагами | «В файле нет ни одного листа со шагами» |
| E03 | danger | на листе в строках 1–3 не найдены `№ шага` и `Шаг` | «Не найдена строка заголовков: нужны колонки „№ шага“ и „Шаг“» |
| E04 | danger | строка не пустая, `Шаг` пуст | «Не заполнено поле „Шаг“» |
| E05 | danger | строка не пустая, `№ шага` пуст | «Не заполнено поле „№ шага“» |
| E06 | danger | `id` повторяется в файле (сравнение после trim) | «Номер шага {id} уже есть на листе {sheet}, строка {row}» |
| E07 | danger | `url` не пуст и не начинается с `http://` / `https://` | «Ссылка не похожа на адрес: {url}» |
| W01 | warning | `url` начинается с `http://` | «Ссылка начинается с http:// — нужен https» |
| W02 | warning | `url` пуст | «Нет ссылки на экран» |
| W03 | warning | ячейка `№ шага` числовая | «Номер шага записан числом — задайте ячейке текстовый формат, иначе 1.10 превращается в 1.1» |
| W04 | warning | `node` не пуст и отсутствует в снимке выбранной карты | «Узел „{node}“ не найден на карте {map} (снимок от {date})» |
| W05 | warning | лист без шагов (есть только заголовки) | «Лист пустой — пропущен» |
| I01 | info | колонка с нераспознанным заголовком, одна строка на лист | «Колонка „{header}“ не распознана и пропущена» |
| I02 | info | нет необязательной колонки, одна строка на лист и колонку | «Колонка „{name}“ не найдена — поле будет пустым» |
| I03 | info | всегда, одна строка | «Узлы проверены по карте {map}, снимок от {date}» |

Строка отчёта: `{ level, code, sheet, row: number | null, message }`. Сортировка: уровень (danger → warning → info), затем порядок листов, затем строка. В таблице колонка «Строка» для `null` показывает «—».

В отчёт не пишется ничего о содержании шагов — только технические проверки.

### 3.6 «Мои» сценарии (`src/state/library.ts`)

- Ключ `localStorage` — `demo-navigator:library:v1`, значение — `{ "schema": 1, "items": Scenario[] }` (у всех `source: 'local'`).
- Чтение — при старте. Весь объект прогоняется через zod; элемент, не прошедший схему, выбрасывается (остальные остаются), и ключ перезаписывается очищенным. Нечитаемый JSON — ключ удаляется, «Мои» пусты.
- `id` нового сценария: `my-` + слаг названия (транслитерация кириллицы как в process-map, `[^a-z0-9]+ → -`, не длиннее 48 символов); занят — добавляется `-2`, `-3`… `id` при замене (§4.8) не меняется, поэтому ссылки `?scenario=my-…` в этом браузере продолжают работать.
- Порядок в каталоге — по `loadedAt`, новые сверху.
- Запись — после добавления, замены и удаления, целиком. `QuotaExceededError` → изменение не применяется, тост «Не хватает места в браузере — удалите ненужные сценарии».
- Все обращения к `localStorage` — в `try/catch` (iframe с `sandbox` без `allow-same-origin` бросает исключение). Недоступное хранилище = «Мои» работают до перезагрузки, в шапке раздела «Мои» подсказка заменяется на «Браузер не даёт сохранять — сценарии пропадут после перезагрузки».
- Активный сценарий и шаг в хранилище **не пишутся** — они живут в адресе (§4.7).

### 3.7 Общие сценарии (`scenarios/`, `scripts/build-scenarios.ts`, `src/state/shared.ts`)

**Источник.** Файлы `scenarios/*.xlsx` в репозитории. Имя файла без расширения — `id` сценария; допустимы `a-z`, `0-9`, `-` (`deployment-demo.xlsx` → `deployment-demo`). Префикс `my-` запрещён — он за «моими».

**Сборка.** `npm run scenarios` (вызывается из `predev` и `prebuild`) для каждого файла:

1. Читает книгу той же функцией `readWorkbook` (§3.3) со снимками карт (§3.4) — Node, SheetJS тот же.
2. Есть `danger` или имя файла не проходит правило → печатает отчёт (файл · уровень · лист · строка · сообщение) в stderr и завершается с кодом 1. Сборка и деплой останавливаются — битый общий сценарий не публикуется.
3. `warning` и `info` печатаются, сборку не останавливают.
4. `loadedAt` — дата последнего коммита файла `git log -1 --format=%cI -- <файл>`; файла нет в git — дата изменения файла. В CI checkout с `fetch-depth: 0`.
5. Пишет `public/scenarios/<id>.json` (полный `Scenario`, `source: 'repo'`) и `public/scenarios/index.json`:

```json
{ "schema": 1, "builtAt": "…", "items": [
  { "id": "deployment-demo", "title": "Deployment — демо-сценарий", "module": "SNP", "map": "snp",
    "fileName": "deployment-demo.xlsx", "loadedAt": "…", "blocks": 3, "steps": 29, "withLink": 24 }
]}
```

Порядок `items` — по `title` (локаль `ru`). Вывод детерминирован. `public/scenarios/` — в `.gitignore`. Пустая папка `scenarios/` — пустой `items`, не ошибка.

**В приложении.** При старте `fetch('./scenarios/index.json')` (относительный путь — `base: './'`). Полный сценарий — `fetch('./scenarios/<id>.json')` при открытии, результат держится в памяти до перезагрузки. Ответ прогоняется через zod. Ошибка сети или схемы → в разделе «Общие» текст «Не удалось загрузить общие сценарии» и кнопка «Повторить»; «Мои» работают.

## 4. Экраны и поведение

Пиксели, отступы и цвета — по `design/Демо-навигатор v2.dc.html`. Ниже — поведение, которого макет не показывает.

### 4.1 Шапка (A0)

56 px, белая, нижняя граница. Справа всегда — кнопка stroked «Загрузить из Excel» с иконкой upload. Слева — по экрану (`design/catalog-mockup.html`, A5 и A0′):

- **Каталог:** монограмма `In·` и «Демо-навигатор».
- **Открытый сценарий:** ссылка «‹ Сценарии» (серый текст, hover — бренд), разделитель `/`, название сценария, `Badge` модуля (если модуль не пуст), `Tag` «общий» или «мой». Клик по «Сценарии» — каталог (§4.7).

### 4.2 Каталог сценариев (A5)

Стартовый экран: в адресе нет `scenario` (§4.7). Макет — `design/catalog-mockup.html`, артборды A5, A5.1, A5.2; снимок — `design/v3-catalog.png`.

- Заголовок «Сценарии» (24/32, 600), справа `SearchField` 320 px «Поиск по названию». Поиск — подстрока без учёта регистра и `ё/е`, фильтрует оба раздела сразу. Ничего не найдено — в разделе строка «Ничего не найдено».
- Контент `max-width: 1120px`, отступ 32 px.
- Два раздела-карточки, сверху вниз: **«Общие»** (§3.7) и **«Мои»** (§3.6). Шапка раздела: подпись верхним регистром, число сценариев (с учётом поиска), справа серая подсказка:
  - «Общие» — «Видны всем. Добавляются файлом в папку scenarios/ репозитория»;
  - «Мои» — «Видны только в этом браузере. Сюда попадает загрузка из Excel».
- Таблица: «Сценарий» (название 600 и имя файла 12 px серым под ним) · «Модуль» (`Badge`) · «Блоков» · «Шагов» · «Со ссылкой» (числа вправо, табличные цифры) · «Обновлён» для общих / «Загружен» для моих · колонка действия 48 px.
  - Дата: сегодня — «сегодня, ЧЧ:ММ»; иначе `ДД.ММ.ГГГГ`.
  - Вся строка — кнопка: клик или Enter открывает сценарий на первом шаге. Hover и фокус — фон `--brand-50`, левый акцент 3 px, справа шеврон ›.
  - У «моих» в колонке действия — иконка корзины «Удалить из браузера» (клик не открывает сценарий). Подтверждение — модальное окно 480 px (A5.2): «Удалить сценарий?», «„{title}“ будет удалён из этого браузера. Файл Excel на компьютере останется.», кнопки «Отмена» и destructive «Удалить». ### 4.3 Схема сценария (A2)

Белая полоса под шапкой. Заголовок «СХЕМА СЦЕНАРИЯ», справа — «{steps} {шагов} · {withLink} со ссылкой».

Блоки — колонки в ряд (`flex: 1 1 0`, `min-width: 220px`), между ними стрелка →; при нехватке ширины — горизонтальная прокрутка полосы, не переносы. Шапка блока: квадрат с номером, название, «{k} {шагов}».

Шаг — кнопка во всю ширину колонки: точка-маркер на вертикальной линии, номер (табличные цифры), заголовок (до 2 строк, `title` — полный текст), справа иконка внешней ссылки, если у шага есть `url`. Активный шаг: фон `--brand-50`, точка и номер `--brand-700`, номер полужирный. Точка неактивного шага со ссылкой темнее, чем без ссылки. Клик — шаг становится активным. Активный шаг прокручивается в видимую область полосы (`scrollIntoView({ block: 'nearest', inline: 'nearest' })`).

Сворачивание блоков из PRD F4 в макете v2 не нарисовано: все блоки раскрыты. В v1 блоки **не сворачиваются** (§11, вопрос 5).

### 4.4 Карточка шага (A3)

Белая карточка, `max-width: 840px`, под схемой. Секции сверху вниз:

1. **Шапка:** «Блок {n} · шаг {k} из {m}», заголовок шага (24/32, 600). Справа две иконки-кнопки ‹ › (§4.5).
2. **Экран.** Есть `url` → название экрана (если есть), кнопка primary «Открыть экран» с иконкой, под ней URL серым 12 px с переносом по символам. Нет `url` → название экрана (если есть) и серый текст «Экран не указан».
3. **Карта процесса** — §4.6.
4. **Действие** — только если заполнено.
5. **Бизнес ценность** — показывается всегда. Заполнено: фон `--brand-50`, левая граница 3 px `--brand-700`, текст 18/28. Пусто: белый фон, левая граница 3 px пунктиром `--brand-200`, серый текст 14/20 «Поле не заполнено. Добавьте бизнес-ценность в колонке „Бизнес-ценность“ файла сценария.»
6. **Ожидаемый результат** — всегда. Пусто: серый текст «Поле не заполнено. Добавьте ожидаемый результат в колонке „Ожидаемый результат“.»
7. **Комментарий** — только если заполнено; 12/16, серый.

Под карточкой — встроенная карта (§4.6), если она раскрыта.

### 4.5 Навигация

- ‹ и › переходят к предыдущему / следующему шагу в сквозном порядке (блок за блоком). На первом шаге ‹ `disabled`, на последнем › `disabled`.
- Клавиши ← и → делают то же, если: сценарий загружен, окно загрузки закрыто, фокус не в `input`, `textarea`, `select` или `[contenteditable]`. Иначе клавиши не перехватываются.
- При смене шага страница прокручивается к началу карточки только если шапка карточки ушла из видимой области.

### 4.6 Карта процесса (`src/pm/pmLink.ts`, `ProcessMapSection`)

Адрес карты (`src/config.ts`):

```ts
pmBase: {
  snp: 'https://igordikinov.github.io/process-map/',
  mrp: 'https://igordikinov.github.io/process-map/mrp/',
}
```

`pmLink(map, node)`: если `node` пуст или его нет в снимке — `null`. Иначе `{ stage, stageTitle, url: pmBase[map] + '?stage=' + stage + '&node=' + encodeURIComponent(node) }`. Формат — по `process-map/SPEC.md §4.7`: узел главнее этапа, `stage` передаётся для читаемости ссылки. Параметр `version` не передаётся — нужна версия карты по умолчанию.

Секция в карточке:

- Узел сопоставлен: «Этап {stage} · {stageTitle}», кнопка stroked primary «Показать на карте» / «Скрыть карту», кнопка stroked neutral «Открыть в новой вкладке» с иконкой; ниже серым «Узел: {node}».
- Не сопоставлен (пусто или W04): серый текст «Узел процесса не сопоставлен».

Встроенная карта — секция под карточкой: заголовок «PROCESS MAP» + название этапа; рамка с горизонтальной прокруткой; `iframe` шириной 100 %, `min-width: 1024px`, высота 760 px, `title="In.Plan Process Map"`, `loading="lazy"`, `referrerpolicy="no-referrer"`.

- Признак «карта раскрыта» — один на приложение, не на шаг: раскрыл на 1.10, перешёл на 1.11 — карта остаётся раскрытой и показывает узел 1.11 (меняется `src`).
- У шага без узла `iframe` не рендерится, даже если признак включён; кнопки нет.
- Признак не сохраняется между перезагрузками.
- «Открыть в новой вкладке» — `window.open(url, '_blank', 'noopener')`.

### 4.7 Deep-link

- `?scenario=<id>&step=<stepId>`. Нет `scenario` → каталог. Есть → открывается сценарий: общий — после загрузки `index.json` и файла сценария, мой — из библиотеки.
- Сценарий не найден → каталог и тост «Сценарий „{id}“ не найден. „Мои“ сценарии есть только в том браузере, где их загрузили» (для `my-…`) или «Сценарий „{id}“ не найден» (для общих). `scenario` убирается из адреса.
- `step` нет или не найден → первый шаг сценария.
- Открытие сценария из каталога → `scenario=<id>&step=<первый>`. Смена шага → меняется `step`. «‹ Сценарии» → `scenario` и `step` убираются. Удалён открытый сценарий (из другой вкладки) → каталог.
- Адрес всегда обновляется `history.replaceState` (не `pushState` — приложение живёт в iframe вики, как process-map). Кнопка «назад» браузера между каталогом и сценарием не работает — это осознанно; возврат — только «‹ Сценарии». Остальные параметры адреса сохраняются.
- Параметры из адреса применяются один раз при старте.

### 4.8 Окно загрузки (A4)

Модальное окно 720 px, затемнение фона, закрытие крестиком, «Отмена», Esc и кликом по фону. Фокус при открытии — на зоне выбора файла; при закрытии возвращается на кнопку, открывшую окно.

**Шаг 1 · Файл.** Зона выбора (пунктир `--brand-700`, фон `--brand-50`): клик открывает `<input type="file" accept=".xlsx">`, работает перетаскивание. Текст до выбора — «Перетащи .xlsx или выбери файл», подсказка «Один лист = один блок». После выбора — имя файла; подсказка «Нажми, чтобы выбрать исправленный файл» при ошибках или «Файл проверен без ошибок». Ссылка «Скачать шаблон». Серый блок «Схема шаблона» — три пункта:

- один лист = один блок; служебные листы начинаются с «_»;
- строка 1 — название блока (необязательно), строка 2 — заголовки: № шага · Шаг · Действие · Экран · Ссылка · Бизнес-ценность · Ожидаемый результат · Комментарий · Узел карты;
- обязательны № шага и Шаг, остальное — по желанию.

Файл не `.xlsx` по расширению → E01 без попытки чтения. Во время разбора зона показывает «Проверяю файл…».

**Шаг 2 · Проверка** — появляется после выбора файла. Сводка §3.3. Таблица «Лист · Шагов» (для блоков: «Блок {n} · {title}»). Таблица отчёта «Уровень · Лист · Строка · Сообщение», уровень — пилюля (`danger` / `warning` / `info` цветами §5). Отчёт длиннее 12 строк — таблица с собственной прокруткой, высота 360 px.

**Совпадение названия (A4′).** Если ошибок нет и в «Моих» уже есть сценарий с тем же названием (сравнение без учёта регистра и пробелов по краям), под отчётом — жёлтый блок: «В „Моих“ уже есть сценарий „{title}“, загружен {дата}.» и два переключателя:

- «Заменить его» (выбран по умолчанию) — содержимое заменяется, `id` сохраняется, `loadedAt` обновляется, сценарий поднимается наверх списка;
- «Добавить как новый — „{title} (2)“» — название получает первый свободный суффикс ` (2)`, ` (3)`…, новый `id`.

С общими сценариями названия не сравниваются: мой сценарий может называться так же, как общий, — их различает `Tag`.

**Подвал.** Слева подсказка «Исправьте ошибки в файле и загрузите снова», если есть `danger`. Справа «Отмена» и primary-кнопка: «Добавить в мои», при совпадении названия — «Заменить» или «Добавить» по выбранному переключателю. Кнопка `disabled`, пока файл не выбран, не разобран или есть `danger`.

Нажатие → сценарий записывается в «Мои» (§3.6), окно закрывается, открывается этот сценарий на первом шаге (адрес `scenario=my-…&step=…`), тост «Сценарий добавлен в „Мои“: {steps} {шагов}» (при замене — «Сценарий обновлён: …») на 3,2 с. Окно открыто из каталога или из сценария — поведение одно. «Отмена» — ничего не меняется.

## 9. Definition of Done для задачи

Код + тесты зелёные (`npm run check`, для UI-задач и `npm run e2e`) + ТК из поля acceptance задачи пройдены + при UI-задаче скриншот сравнён `visual-qa` с артбордом + `excel-auditor` для задач с меткой `excel` + `bd close <id> "…"` с кратким описанием.

## 10. Организация работы

### 10.1 Принципы

- **Оркестратор (главная сессия) кода не пишет.** Ведёт beads, вызывает субагентов, принимает результат, коммитит, закрывает задачи, делает push. Любая правка файлов — через `developer`.
- **Одна задача bd — один claim — один диф.** Параллельно — не больше двух задач и только без общих файлов. `src/model/schema.ts`, `src/excel/columns.ts`, `src/state/store.tsx` — общий контракт: правит один агент, остальные ждут (`bd dep add`).
- **Субагент получает выжимку, а не всю спеку.** `spec-reader` вырезает нужные разделы (§3.x, §4.x, ТК §8) и передаёт дальше.
- **Тесты не подгоняются под код.** `developer` не правит `tests/` и `e2e/`, если задача — не «написать тест». Изменение ожидаемого значения — отдельная задача с обоснованием.
- **Контракт §3.2–3.5 = код.** Любая задача с меткой `excel` проходит `excel-auditor` до закрытия: коды, тексты, уровни проверок и алиасы сверяются построчно.
- **Не выдумывать.** Нет в SPEC — задача `-t decision` со ссылкой на §11, а не догадка. `design/` не менять.

### 10.2 Трекер beads

`.beads/` в корне репо, коммитится вместе с кодом. Инициализация: `bd init --prefix DN`, затем `bd hooks install --beads` (экспорт `.beads/issues.jsonl` — как в process-map, `export.auto: true`, `export.git-add: true`).

Поля: `title` · `type` (task / bug / chore / decision) · `priority` (0 блокер … 3 фон) · `labels` (`ф1`, `ф2`, `ф3`, `excel`, `ui`, `pm`, `ci`, `docs`) · `deps` · `design` (раздел SPEC) · `acceptance` (номера ТК §8).

Команды оркестратора (точный синтаксис флагов сверить с `bd --help` при первом запуске):

```bash
bd prime                                                        # контекст в начале сессии
bd create "Разбор листов Excel" -t task -p 1 -l ф1,excel \
  --design "SPEC §3.2, §3.3" --acceptance "ТК 1, 5, 6, 7, 9"    # завести задачу
bd dep add DN-06 DN-05                                          # DN-06 зависит от DN-05
bd ready                                                        # что можно брать
bd show DN-06                                                   # карточка перед стартом
bd update DN-06 --claim                                         # взять в работу
bd update DN-06 --status in_progress                            # если claim не двигает статус
bd close DN-06 "что сделано, какие ТК зелёные"                  # закрыть после проверок
bd blocked                                                      # что стоит и почему
bd list -l ф1                                                   # состояние фазы
bd remember "SheetJS: cell.w пуст у ячеек из writeFile без cellText"  # долговременная заметка
```

Правила: задача не закрывается без зелёного `test-runner`; блокирующий вопрос — задача `-t decision -p 0` со ссылкой на §11; новая работа, найденная по ходу, — новая задача, а не молчаливая правка.

### 10.3 Субагенты

Переиспользуются определения из `snp-architecture/.claude/agents/` — **копируются** в `.claude/agents/` этого репо (репо отдельный): `planner`, `explorer`, `test-runner`, `code-reviewer`, `verifier`, `doc-writer`. В `test-runner`, `code-reviewer` и `verifier` дописаны правила этого репо (test-runner правит только `tests/` и `e2e/`). Новые — `spec-reader`, `developer`, `excel-auditor`, `visual-qa` (§10.4).

| Агент | Когда | Вход | Выход | Права |
|---|---|---|---|---|
| `spec-reader` | первым в каждой задаче | id + SPEC | выжимка: разделы, тексты, коды, ТК, краевые случаи | чтение |
| `explorer` | неясно, где код | вопрос | `файл:строка` | чтение |
| `planner` | задача трогает > 1 файла | выжимка | план правок по файлам | чтение |
| `developer` | после плана | план | диф | запись в `src/`, `scripts/`, конфиги; не `tests/`, `e2e/`, `design/` |
| `test-runner` | после каждого дифа; для задач «написать тест» — пишет тесты | диф / ТК | результат `npm run check` / `npm run e2e`, упавшие кейсы | запись в `tests/`, `e2e/`, запуск |
| `code-reviewer` | после зелёных тестов | диф + раздел SPEC | замечания или «ок» | чтение |
| `excel-auditor` | задачи с меткой `excel` | §3.2–3.5 + код `src/excel/` | построчная сверка, вердикт | чтение, запуск тестов |
| `visual-qa` | задачи с меткой `ui` | номер артборда | список визуальных отличий | запуск dev-сервера и Playwright |
| `verifier` | приёмка фазы | фаза + §8 | факт-чек по ТК | чтение, запуск |
| `doc-writer` | конец фазы | список изменений | README, CHANGELOG | запись в `README.md`, `docs/` |

### 10.5 Цепочки

**По задаче:**

```
bd ready → bd show DN-NN → bd update DN-NN --claim
  → spec-reader (выжимка)
  → [explorer, если неясно где код]
  → planner (план)
  → test-runner (тесты по ТК, если их ещё нет — красные)
  → developer (диф)
  → test-runner (зелёный прогон)
  → code-reviewer (замечания → developer, пока не «ок»)
  → excel-auditor (метка excel) / visual-qa (метка ui)
  → оркестратор: коммит, bd close DN-NN
```

**По фазе:** все задачи фазы закрыты → `verifier` по ТК фазы → замечания = новые задачи → `doc-writer` → оркестратор: push.

**Git:** ветка на задачу `dn-NN-краткое-имя`; сообщение коммита начинается с `DN-NN` (`DN-06 feat: проверки Excel E01–E07`); push — только оркестратор после закрытия задачи. Концовка коммита — строки атрибуции из инструкций сессии.
