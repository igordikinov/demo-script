# PRD — Навигатор демо-сценария (In.Plan Demo Navigator)

Версия 1.1 · 16.09.2026 (1.1 — каталог сценариев: общие и мои) · владелец: Igor D

## 1. Проблема

Сценарии показа In.Plan живут в docx и xlsx. На демо ведущий держит сценарий на втором мониторе, руками ищет нужный экран на стенде и по памяти формулирует, что клиент должен вынести из шага. Связь шага сценария с процессом планирования (где этот шаг в E2E-процессе) нигде не видна, хотя карта процесса уже есть — In.Plan Process Map.

## 2. Цели

- Загрузить сценарий показа из Excel без участия разработчика.
- Показать сценарий как список блоков и шагов; у каждого шага — карточка: экран, действие, бизнес-ценность для клиента, ожидаемый результат, комментарий.
- Из шага одним кликом открыть экран In.Plan в новой вкладке.
- Из шага показать место этого шага на карте процесса (Process Map) — встроенной картой и ссылкой в новую вкладку.
- Хранить несколько сценариев и выбирать нужный в каталоге: **общие** (файлы в репозитории, видны всем) и **мои** (загружены из Excel, живут в этом браузере).

## 3. Не-цели (v1)

- Режим ведущего, таймеры, хронометраж, заметки по ходу показа.
- Управление общими сценариями из приложения: общие добавляются только файлом в репозиторий.
- Перенос «моих» сценариев между браузерами и компьютерами.
- Папки, теги и группировка в каталоге.
- Реестр экранов, подстановка стенда, проверка доступности экранов.
- Скриншоты экранов.
- Редактирование сценария в приложении. Источник правды — Excel-файл.
- Бэкенд, авторизация, серверное хранение.

## 4. Пользователи и сценарии

**Автор сценария (пресейл, методолог).** Заполняет шаблон Excel: лист на блок, строка на шаг, ссылки на экраны и узлы карты. Загружает файл, видит отчёт проверки, исправляет ошибки в Excel и загружает снова — сценарий появляется в «Моих». Готовый сценарий для всей команды кладёт в папку `scenarios/` репозитория — после публикации он в «Общих».

**Ведущий демо.** Открывает навигатор (в вики или по ссылке), выбирает сценарий в каталоге или приходит по ссылке сразу на нужный сценарий, идёт по шагам стрелками, из карточки открывает экран на стенде, при вопросе «а где это в процессе» раскрывает карту.

## 6. Нефункциональные требования

- Статический бандл (Vite + React), без сервера; хостинг — GitHub Pages, как у Process Map. Встраивается в вики In.Plan через `iframe`.
- Первая отрисовка < 1 с; бандл ≤ 350 KB gzip (включая библиотеку чтения xlsx); разбор файла на 300 шагов < 500 мс.
- Интерфейс только на русском, строки вынесены в один файл.
- Визуальный стиль — по макету Claude Design `design/Демо-навигатор v2.dc.html` и макету каталога `design/catalog-mockup.html`: токены In.Plan, Open Sans, акцент `#9000FF` только на активном шаге, primary-кнопках и блоке бизнес-ценности.
- Chrome / Edge последних двух версий, ширина 1024–1920, высота фрейма от 640.

## 7. Данные

Источники — Excel-файлы: общие в папке `scenarios/` репозитория, мои — загруженные в браузере. Эталонное наполнение — сценарий Deployment из прототипа (3 блока, 29 шагов) под нейтральным названием «Deployment — демо-сценарий»; собирается в фикстуру. Узлы карты берутся из снимка карты SNP репозитория `process-map`; в прототипе 4 из 27 сопоставлений указывают на несуществующие узлы (SPEC §3.4) — именно такие ошибки ловит проверка F2.

## 8. Метрики успеха

- Эталонный сценарий Deployment загружается из файла без ошибок и проходит показ без правок вручную.
- Автор загружает новый сценарий без участия разработчика.
- 100 % ссылок на узлы карты в эталонном файле ведут на существующий узел (проверяется тестом).

## 9. Риски

- Excel превращает номер шага `1.10` в число `1.1` — дубль и неверный порядок. Шаблон задаёт текстовый формат колонки, разбор берёт отображаемый текст и предупреждает (SPEC §3.3).
- Вики может встраивать фрейм с `sandbox` без `allow-popups` — тогда «Открыть экран» не сработает. Требование к встраиванию — как у Process Map (SPEC §7).
- Карта процесса меняется в своём репозитории, снимок узлов устаревает. Снимок пересобирается командой, дата снимка видна в отчёте проверки (SPEC §3.4).
- Общие сценарии публикуются вместе с приложением: при публичном репозитории и GitHub Pages их может открыть любой. До решения владельца (SPEC §11, вопрос 6) — никаких имён заказчиков в `scenarios/`.
- «Мои» сценарии живут в одном браузере: очистка данных сайта их удаляет, на другом компьютере их нет. Это сказано на экране каталога.
- npm-пакет `xlsx` 0.18.5 содержит известные уязвимости — библиотека ставится с `cdn.sheetjs.com` с фиксированной версией (SPEC §1).

## 10. Этапы поставки

1. **Ф1 — Каркас и данные**: проект, токены, модель, разбор Excel, проверки, шаблон, фикстуры, сборка общих сценариев.
2. **Ф2 — Экраны**: стор и библиотека «моих», шапка, каталог, схема сценария, карточка, навигация, окно загрузки, удаление.
3. **Ф3 — Карта и поставка**: секция «Карта процесса», deep-link на сценарий и шаг, e2e, сборка, GitHub Pages, инструкция встраивания.
